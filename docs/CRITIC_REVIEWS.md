# 严苛产品评审

每次评审以证据、影响、方案、执行和验证为准。这里是同一执行者切换审查视角后的检查记录，不冒充独立第三方审计。

## 01 / 构想与纵向切片
- 问题：容易成为“换皮决策矩阵”，分数制造客观性错觉。
- 证据：只有静态加权分无法回答为什么选择、后来是否成立。
- 影响：用户会追逐最高分，无法形成可复用认识。
- 方案：自动推荐 AI 或透明证据与实践闭环；选后者，避免外部依赖与无法解释的建议。
- 实施：即时调权、排名翻转、成分光谱、五点敏感度、真实证据修正；锁定假设与信号、服务端构造不可变快照，复盘记录支持/混合/推翻。
- 验证：双端独立数值测试，浏览器真实翻转并完成实践与复盘；锁定后 UI 与 API 都拒绝修改。

## 02 / 核心体验与可靠性
- 问题：最初示例权重使修补方案已经领先，演示不展示设计的转折；认证密码编码缺失。
- 证据：Vue 断言失败，Java Security 测试抛出密码编码异常。
- 影响：核心体验说服力受损，生产账号无法登录。
- 改进：明确样例的取舍，修正权重；使用 BCrypt 正确编码前缀，不降低校验。
- 实施：示例初值 40/20/40；基础数值独立手算测试；补充真实浏览器私有登录与写入。
- 验证：Java 认证测试、真实 HTTP 401/200、浏览器错误密码/正确密码与 CSRF 写入通过；初始书房 7.80，权重变化后修补方案领先。

## 03 / 可访问性与数据保管
- 问题：辅助文字对比度低；移动端隐藏了归档入口；只有导出，没有恢复。
- 证据：Chromium 实图和 axe color-contrast 违规；响应式 CSS 隐藏筛选；早期仅 GET backup。
- 影响：低视力用户阅读困难，手机用户不能找回归档，备份无法形成可靠闭环。
- 方案：保留设计语言，增加文字对比、显示移动搜索筛选；只追加 JSON 导入并以事务校验快照，避免覆盖用户数据。
- 实施：统一加深次要文字、原生控件与键盘方向导航、模态框焦点管理；导入格式/引用/快照/体积限制。
- 验证：三个工作区的 WCAG A/AA 自动检查无违规；390px 无页面横向溢出；浏览器导出/导入通过；失败导入整批回滚由独立 HTTP 测试证实。

## 04 / 工程与运维
- 问题：开发工具依赖存在已知漏洞，初次兼容补丁仍未全部修复；容器无法解析平台代理且不信任平台 CA。
- 证据：npm audit 先报告 4 个漏洞，补丁后仍有 3 个；干净 Node 容器报 SELF_SIGNED_CERT_IN_CHAIN，桥接网络 TCP/DNS 不可用。
- 影响：开发工具安全风险、部署不可复现。
- 改进：更新到兼容 Node24 的 Vitest5.0.5 与 Vite7.3.7；构建通过当前平台代理，挂载已信任公共 CA。
- 实施：精确版本与锁文件；代理感知 Maven wrapper；BuildKit 临时设置与公共 CA；不关闭任何证书或制品验证。
- 验证：npm audit 零已知漏洞；全套测试与 Docker 源构建通过；UID10001、健康与真实认证写入、命名卷重启、停机文件恢复均验证。首次运维 chown 被 cap_drop 拒绝，改为仅临时恢复操作添加 CHOWN/FOWNER 后验证成功，普通服务仍丢弃全部能力。

## 05 / 最终容量与隐私审查
- 问题：上限 500 项时，仅导出与归档不会释放容量；用户也无法真正移除误录的敏感记录。
- 证据：存储上限统计包含归档项，原先没有删除 API。
- 影响：长期使用最终无法继续创建，隐私操作不完整。
- 方案：增加仅归档后可用的永久删除，而不自动清理或覆盖历史。
- 实施：标题输入确认、归档状态约束、版本校验、条件 DELETE；补充 Java 与浏览器流程测试；文档说明不是物理安全擦除。
- 验证：Java 归档/版本/删除约束与浏览器数据库404断言均通过，最终合计13 Java、5 Vue、5浏览器。

## 最终判断
1. 最值得保留的原创表达：可操作的取舍光谱与不改写过去的实践回声连成一个闭环；不声称首创加权矩阵。
2. 超越传统网站的部分：页面不仅存放内容，权重变化成为探索判断的工具，快照使结果能回到当时的语境。
3. 最薄弱部分：信心和评分仍来自用户，五点敏感度可能遗漏狭窄翻转区间。界面已说明；连续敏感度与真实用户研究属后续增强。
4. 严重缺陷：按最终回归记录判断；发现阻断立即继续，不用“还有空间”拖延交付。
5. 大规模重构：当前聚合、有限规模、模块分工符合单人使用，无充分收益证明需要重做。
6. 真实用户可用：核心流程、持久化、恢复、错误与身份保护可独立使用；产品价值仍需真实使用研究。
7. 交给开发者：构建、运行、容器与备份恢复有文档和执行证据；另一台机器及公网 HTTPS 未验证，必须由部署者完成对应检查。

## 06 / 运行模式一致性
开发启动脚本原先工作目录为 backend，默认数据库会与打包运行的数据目录不同；真实开发启动验证发现这一差异。已用 PRISM_DATABASE_URL 显式统一到根目录 data，保留用户传入的配置。重新启动开发模式，验证 Vite、同源 API 与日志中的根目录数据库路径；停止开发后再用打包运行验证相同空库。解决模式切换时“数据消失”的误解，无需修改产品规则。
