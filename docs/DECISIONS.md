# 决策记录

- ADR-001：选折光工作室，理由见愿景。拒绝为了创新引入不可检验 AI 与外部依赖。
- ADR-002：Java 21 + Spring Boot 3.5.16。版本从 Maven 元数据验证存在，使用 Boot BOM 管理兼容依赖。
- ADR-003：嵌入式 H2 + JDBC 文档聚合。适配单人私有部署，免去数据库服务运维；不声称支持多实例并发部署。
- ADR-004：前端即时预演、后端权威规则。双方公式由独立预期值测试、真实 API 与浏览器链路验证；不使用前端分数直接锁定。
- ADR-005：锁定而非任意改历史。错误判断仍应被保留，新一轮从新记录开始。
- ADR-006：明确信心是用户提供的权重折减，不是模型置信区间，敏感度是五点采样。
- ADR-007：单人所有者 Basic + CSRF，同源打包。避免引入无需求的注册与密码重置系统，生产要求 HTTPS 反向代理。
- ADR-008：备份导入只追加，不覆盖；数据库恢复走停机物理备份。用数据可靠性补齐导出闭环。
- ADR-009：前端依赖审计发现开发工具已知漏洞，Vite 升至 7.3.7、Vitest 先升级 3.2.7，复查仍有漏洞后升至 5.0.5（Node 24 兼容，全部测试重跑通过）。具体结果记录于测试文档。
- ADR-010：初次研发不执行公网部署与远程推送；Docker 与本机验证仅在当前隔离机器内执行。
- ADR-011：用户随后明确要求推送至 Git main，允许创建首次提交并正常推送 origin/main；不强制覆盖远程历史、不改变仓库可见性、不部署公网。
